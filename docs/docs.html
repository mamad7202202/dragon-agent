Getting started

Install

One line on Linux/macOS:

curl -fsSL https://raw.githubusercontent.com/mamad7202202/dragon-agent/main/install.sh | sh

And on Windows PowerShell:

irm https://raw.githubusercontent.com/mamad7202202/dragon-agent/main/install.ps1 | iex

The scripts download a single static executable into your user bin directory and wire up PATH. Prefer cargo? cargo install --git https://github.com/mamad7202202/dragon-agent. The desktop app (dragon-gui) is an optional separate download from releases.

First run wizard

Launch dragon (or the desktop app) with no config and an interactive setup walks you through three questions: provider → key → models. In the TUI you navigate with ↑ / ↓ and confirm with space or enter; typing is always accepted too. Re-run any time inside the TUI with /setup, or from your shell:

# Google AI Studio (Gemini) - has a free tier
dragon setup --preset google --key AIza...

# OpenRouter - one key, hundreds of models
dragon setup --preset openrouter --key sk-or-...

# fully local, no cloud
dragon setup --preset ollama

Providers & models

Dragon speaks two protocols: OpenAI-compatible chat-completions and Anthropic's native Messages API - both streamed over hand-rolled SSE for instant first tokens.

Modes: chat · plan · agent

  • chat — pure conversation, no tools. Cheapest way to think out loud.
  • plan — read-only research (read, list, grep, fetch). The reply must be a concrete numbered plan; nothing on disk changes.
  • agent — the full toolkit below, gated by permissions.

Set per session: TUI /mode plan or Ctrl+M to cycle; desktop uses the chips in the header. The default mode lives in settings.

The permission gate

Tools that change the world — write_file, edit_file, delete_file, run_shell — pause the agent and show an approval card:

  • allow — runs this once.
  • always allow — remembers the choice per tool (patterns like run_shell:npm allow only npm-prefixed commands).
  • deny — the model is told "user denied" and adapts instead of retrying.
  • what does this do? — asks the model for a neutral, ≤3-sentence explanation of exactly what this action would do to your machine, independent of the task. Shown inline before you decide.

Esc always hard-stops a running turn — including while an approval is pending.

The memory system

Dragon's memory is deliberately split so the model gets maximum signal for minimum tokens:

Two scopes of facts

  • session facts — learned inside this conversation (project layout, decisions, file paths). They never leak into other sessions.
  • global facts — durable user knowledge ("prefers dark mode", team conventions) available everywhere.

Plus procedural memory: a plain MEMORY.md whose standing instructions are always loaded, and episodic transcripts — every session is a resumable JSONL log.

How recall stays cheap

Each turn, candidate facts are scored:

score = relevance × (0.55 + 0.45·importance) × (0.7 + 0.3·recency) × scope_boost
scope_boost = 1.35 session-fact | 1.0 global | 0.85 other-session leftover

Only the top-k winners enter the prompt as a short block — everything else stays on disk. Long conversations additionally compact: old turns are folded into an LLM summary once history passes the threshold (settings), keeping recent context verbatim. No vector database, no embedding bills — recall runs locally in microseconds.

Sessions

Every conversation gets an id, a title derived from your first message and a transcript on disk. Resume any past session with its full history, mode and memories:

/sessions        # numbered list, newest first
/resume 2        # continue it (CLI)
Ctrl+S           # session popover (desktop)
Shared brain. A session started in the terminal appears in the desktop app's session list and vice-versa — same files, same memories.

Desktop app

A glassy native window around the same core:

  • Chat — streaming bubbles, markdown-lite, copy buttons, approval cards with the explainer.
  • Sessions popover — resume anything, start fresh (Ctrl+S / Ctrl+N).
  • Memory browser — search, scope badges (session/global/other), forget.
  • Providers — collapsible cards, click a model to make it current, modal add-form with presets.
  • Settings — default model, shell gate, compaction threshold, light/dark theme (Ctrl+D).

Full shortcut sheet: press ? inside the app.

Updates

On every launch both apps ping GitHub's releases API. When a newer version exists you'll see a banner (desktop) or footer note (TUI) linking straight to the release page. Releases are versioned vX.Y.Z with raw executables plus checksums.txt, and the installers always fetch the newest stable build.

FAQ

Where do my keys live?
Only in your local config file. Nothing is sent anywhere except the provider you chose.

Is my code uploaded?
No telemetry exists in either binary. Tool outputs go to the model provider you configured, like any LLM request.

Does the GUI need the CLI installed?
No — they're independent binaries sharing optional files. Install either or both.

Windows says "unknown publisher"
Binaries aren't code-signed yet; verify against checksums.txt and run.
